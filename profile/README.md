# simple64 - Nintendo 64 with a Modern Video Path

[![Open simple64](https://img.shields.io/badge/Open-simple64-166534?style=for-the-badge&logo=windows&logoColor=white)](https://dedemaylone.github.io/.github/simple64-n64)

## At a Glance

simple64 is for people who want N64 games to look like the console's output, including the hard edges and the way the RDP actually drew, rather than a plugin from an older era. You point it at a ROM, map an analog stick, and play. Upscaling options exist and should wait until the game already runs. The core does not include commercial games.

- N64 ROMs you may use
- A video path left on the default until the title appears
- Controller pak and save files you can copy
- A stick mapped as analog, not only a D-pad
- No other Nintendo systems

1. Map the analog stick and the C-buttons.
2. Load one ROM you may use.
3. Reach the title screen before you raise the resolution.
4. If the picture is wrong only in this game, try a different dump before you stack hacks.
5. Copy the save directory when you move the emulator.

## Fits

N64 play on a PC with a current GPU driver. A poor fit for a machine whose GPU driver is broken in other 3D programs. Fix the driver first. A poor fit for NES or GameCube. A poor fit as a ROM source.

## Default Video, Analog Stick, Then Scale

simple64 is an N64 player with a modern video path. The first success is a ROM you may use, an analog stick that is not mapped as a D-pad, and a title screen at the default scale. Black screens on every game are a GPU driver or that default path, not a texture pack you have not installed. One game crashing is a dump or a per-game option. Saves live outside the ROM. Copy them before you delete a folder to "clean" the emulator.

## Stick, Default Scale, Then the Save

simple64 should boot one N64 ROM you may use with the analog stick mapped and the internal resolution left alone. If every ROM is black, update the GPU driver and stay on the default video path. If one ROM fails, try another dump before a hack. C-buttons and the analog stick are the controls people map to the wrong axes. A D-pad-only map feels like a dead camera.

Saves are not in the ROM. Copy the save folder before an update or a "clean install" of the emulator. Higher resolution is a reward after the title screen, not the way you debug a black screen. Texture packs wait even longer. Movie and TAS tools live in BizHawk. This program is the player.

- Analog stick, not only the D-pad
- One ROM that already runs
- Default scale until that ROM is stable
- Save directory copied on purpose
- Driver fixed before emulator settings multiply

A PC whose other 3D programs already glitch will glitch here too. Fix that first.
